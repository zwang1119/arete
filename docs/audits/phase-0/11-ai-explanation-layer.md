# Phase 0 Audit 11 — AI & Explanation Layer

> Status: audit complete; no production implementation changes made  
> Date: 2026-08-15

## 1. Purpose

AI should make ARETE easier to understand and interact with. It should not become an alternative authority path that can bypass canonical data, evidence rules, safety precedence or plan-mutation governance.

## 2. Current strengths worth preserving

The existing ARETE architecture already leans toward deterministic reason IDs, structured decisions and separate Athlete/Coach views. This is an excellent base because an LLM can explain an existing decision instead of inventing one.

## 3. Critical findings

### 3.1 Narrative generation must be downstream of authoritative state

The AI should receive already-computed facts, assessments, decisions and provenance. It should not independently recalculate performance, progress, readiness or plan adherence from raw provider payloads when authoritative domain outputs exist.

### 3.2 Free-text extraction is probabilistic

Athlete notes contain valuable context (pain, equipment changes, traffic, illness, RPE explanations), but an LLM extraction is a candidate interpretation. Material extracted facts require validation or explicit confidence before they can change authoritative state.

### 3.3 User/provider text is untrusted input

Imported workout titles, descriptions, calendar notes and provider payloads must be treated as data, not instructions to the AI. This matters both for accidental ambiguity and prompt-injection-style content.

### 3.4 AI must not invent scientific thresholds or citations

The model may retrieve and summarize approved EvidenceRecords. It must not create a new rule because it “knows” a common coaching heuristic.

### 3.5 AI must not mutate plans silently

Any requested plan change must become a structured candidate action routed through the Decision/PlanMutation pathway.

### 3.6 Explanation should use reason codes, not hidden reasoning

ARETE does not need to store or expose model chain-of-thought. It needs concise, inspectable explanations grounded in structured inputs, reason IDs, evidence references and uncertainty.

### 3.7 Model updates can change language behavior

AI output is not deterministic in the same way as the rule engine. Important structured outputs need schemas, validation and regression tests; model/provider/version should be auditable where necessary.

### 3.8 Data minimization applies to AI context

Do not send an entire lifetime record when a small subset is sufficient. Sensitive symptom/body/photo data should be included only when relevant and permitted.

## 4. Appropriate AI roles

Good uses:

- explain decisions;
- summarize longitudinal patterns already computed;
- translate structured state into natural language;
- answer athlete questions using canonical records;
- identify candidate structured facts in notes;
- compare alternatives already generated by deterministic logic;
- assist evidence/code review in development.

Bad authority uses:

- inventing thresholds;
- silently selecting authoritative sources;
- diagnosing injuries;
- recomputing official metrics differently from Core;
- fabricating missing data;
- changing history;
- autonomous plan rewrites outside governance.

## 5. Audit verdict

**AI SHOULD BE A NARRATIVE/INTERACTION LAYER WITH VALIDATED STRUCTURED SIDE EFFECTS, NOT THE COACHING KERNEL.**

## 6. Required tests

1. AI explanation matches DecisionRecord reason codes;
2. imported note containing instruction-like text cannot override system policy;
3. material symptom extracted from free text remains candidate until validated according to policy;
4. AI cannot invent a citation/reference ID;
5. AI plan suggestion cannot bypass PlanMutationRequest;
6. missing metric is described as missing, not guessed;
7. provider/model change does not alter deterministic underlying decision;
8. only relevant sensitive context is sent;
9. Coach Lens can reconstruct the non-AI decision path;
10. AI outage leaves core ARETE functionality usable.
